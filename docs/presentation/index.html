Motivation & Background

The Dilemma: Isolated Silos vs Centralized Clouds

Traditional Self-Hosting
Plex / Jellyfin Silos
  • Private Island: Media files trapped on home PC with zero global or community discovery.
  • CGNAT Barrier: Residential ISPs block incoming ports; requires risky manual port forwarding.
  • Upload Collapse: Multiple concurrent remote viewers directly saturate home upload bandwidth.
Centralized Cloud
YouTube / Cloud S3
  • Compounding Storage Fees: Terabytes of permanent cloud storage billed continuously.
  • Custody Loss: Video binaries surrendered to centralized hosting servers.
  • Egress Bandwidth Tax: Crushing cloud transfer charges make indie community apps financially impossible.
The CustardFin Answer
Best of Both Worlds
  • Video Stays Home: Owner retains 100% physical ownership and sovereignty.
  • Outbound Tunnels: TLS reverse tunnel punches effortlessly through residential CGNAT.
  • Origin Shield: Central cache serves viral viewers; home uploads each hot segment only once!
Architectural Foundation

Invariant 1: Zero Cloud Video Storage Footprint

Traditional Cloud Approach
Permanent Central Storage
  • Every uploaded video occupies permanent S3/GCS gigabytes billed month after month.
  • 1,000 community videos = ~4 TB permanent storage footprint ($100+/mo).
  • Central cloud is a high-value target for data leaks and centralized takedowns.
  • The cloud provider owns the physical drive where your video files reside.
CustardFin Invariant 1
Lightweight ~3 KB Manifests
  • Video files strictly live on the owner's hard drive and edge SQLite database.
  • Publishing to the community catalog syncs ONLY a ~3 KB JSON manifest:
    { media_id, content_hash, duration_s, renditions[] }
  • Origin Shield temporarily buffers hot 4s chunks with 24-hour LRU auto-purge.
  • A single $5/month cloud VM can coordinate discovery for 100,000+ community videos!
System Architecture

Two-Tier Topology: Home Edge & Cloud Control Plane

Tier 1: Home Edge Node
Edge Go Daemon (edged)
  • Ultra Lightweight: Single static Go binary (<20 MB idle RAM footprint).
  • SQLite WAL: Local database for video paths, hashes, and private watch progress.
  • Managed Transcoder: FFmpeg subprocess with automatic NVENC probe & CPU fallback.
  • Outbound FRP Client: Establishes outbound TLS reverse tunnel. Zero port-forwarding.
  • Local Streamer: Serves LAN viewers directly on :8090 with 0ms cloud latency.
Tier 2: Cloud Control Plane
Cloud API (apid) & Web UI
  • Cloud API (Go): High throughput REST routing with goroutine workers.
  • PostgreSQL: Stores user accounts, node registry, and 3 KB video catalog manifests.
  • Redis Heartbeats: Ephemeral key heartbeat:{node_id} (15s TTL) for node liveness.
  • S3 Origin Shield: Pull-through chunk cache (MinIO / Floci) with HMAC signed URLs.
  • Next.js 15 UI: App Router with SSR, hls.js player, and Dev Settings Console.

Stream Router

Intelligent Play Decision Engine (Stream Router)

Decision 1
Node Liveness
  • Checks Redis heartbeat TTL
  • If missing: node is offline
  • Serves cached chunks if ready
  • Returns clear offline status
Decision 2
Direct LAN
  • Detects viewer on same subnet
  • Redirects directly to :8090
  • 0 ms cloud relay latency
  • 0 cloud egress bandwidth
Decision 3
Cache Hit
  • Checks S3 Origin Shield cache
  • Issues short-lived HMAC URL
  • Serves directly from S3/CDN
  • 0 bytes drained from home!
Decision 4
Cache Miss
  • Checks 10-stream node cap
  • Pulls once via FRP tunnel
  • Saves chunk into S3 cache
  • Subsequent viewers hit cache!
Invariants 7 & 10

Origin Shield Cache & 10-Stream Admission Control

Invariant 7: Origin Shield
Viral Traffic Protection
  • Home node uploads each hot 4-second video segment ONCE.
  • Central S3-compatible cache stores chunk with 24-hour LRU auto-purge.
  • 100 viewers watching the same title = 99% cache hit ratio!
  • Home residential internet upload bandwidth sees load equivalent to exactly 1 viewer.
  • Verified live via multi-viewer benchmark scripts (load-10-viewers.ps1).
Invariant 10: Capacity Limiter
10-Stream Per-Node Cap
  • 10 viewers watching 10 DIFFERENT titles = 0% cache hit (upload speed is physical limit).
  • Strict per-node concurrency tracker implemented in Go Cloud API.
  • 11th remote viewer receives: HTTP 429 Too Many Requests.
  • Includes Retry-After: 30 header with clear "Node Busy" notice.
  • Adaptive bitrate ladder pruning dynamically filters high-bitrate renditions under network contention.
Milestone 9 Benchmarks

Hardware Acceleration: NVIDIA NVENC vs CPU Benchmark

Transcoder Engine
Dual-Path Architecture
  • Probe Order: NVENC → Intel QSV / VAAPI → Multi-threaded CPU libx264.
  • Strict Alignment: -g 120 -keyint_min 120 -sc_threshold 0 locks I-frames to 4.0s boundaries.
  • Resilient Fallback: 1-second startup test probe validates encoder health; any failure immediately reverts to CPU without crashing.
Empirical Benchmark Data
RTX 4060 vs Intel CPU
  • NVIDIA NVENC (ASIC): 1.21s transcode time (12.4x real-time) with < 3% CPU utilization.
  • Software libx264 (CPU): 5.42s transcode time (2.7x real-time) with 92% peak CPU load across all cores.
  • Result: NVENC provides 4.5x faster throughput and completely protects CPU resources for streaming and OS responsiveness.
